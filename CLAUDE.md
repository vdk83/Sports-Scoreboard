# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

MicroPython scoreboard for a Pimoroni Interstate 75 W (RP2350) driving a 64x32 HUB75 panel. It follows MLB, NFL, NHL, NBA and MLS teams (ESPN + MLB Stats APIs), serves a settings page on port 8080, and is updated over WiFi. See README.md for the file table and features.

## Commands

- Tests (run on the computer, no board needed): `python3 -m unittest test_logic test_app test_critters`
- One test: `python3 -m unittest test_app.TestClass.test_name`
- CI (`.github/workflows/test.yml`) runs the unittests plus `py_compile` on every .py file.
- Preview cameos/layouts without hardware: `python3 preview.py cameos|games|clock`
- Deploy: `python3 deploy.py [host]` (use the address shown on the panel at startup; key in `.ota_key`). Sends only changed files, then the board restarts. New `.py` modules must be added to `FILES` in deploy.py (and to the `mpremote cp` list in README for first USB install).
- Check the board: `curl -H "X-Key: $(cat .ota_key)" http://<board address>:8080/status` (also `/log`, `/export`).
- `main.py` and `secrets.py` are never sent over WiFi; changing them needs USB (`mpremote`).
- `teams.py` is generated by `make_teams.py`; edit the generator, not the output. The `extras_*.py` cameos are hand-written; after adding one, run `python3 make_extras_table.py` to rewrite the EXTRAS table in critters.py, and add the new file to deploy.py `FILES`.
- Extras load lazily only while a cameo plays (`critters.make()`/`release()`) to save RAM; repeated loads fragment the heap, so a `MemoryError` on a score poll is retried, not fatal.

## Architecture

- `main.py` is a minimal launcher: it starts `app.py` and rolls back to `*.py.bak` if new code fails to start 3 times (marker file `ota_try`, cleared by `ota.healthy()`).
- `app.py` holds `Scoreboard`: one cooperative loop (`tick()`), no threads. Network work is split into jobs (per sport/team) with exponential backoff; the hardware watchdog is fed in the loop; a daily 4AM restart and memory logging run in `watch()`. `Scoreboard.web()` is the handler `ota.Server` calls for the settings page, `/log`, `/export`, `/import`, `/teams`.
- `ota.py` is the HTTP server (non-blocking, several connections) that does both OTA (`/hashes`, `/f/<name>`, `/apply`) and delegates everything else to the app handler. Every request needs the OTA key (`X-Key` header or `?k=`).
- `settings.py` is plain Python (also runs on the computer): `cfg`/`DEFAULTS`/`LIMITS`, `config.json`, the log ring buffer, and `cache.json` so the screen isn't empty after restart. New settings need a DEFAULTS entry, a LIMITS entry (numbers), a form control in `page.py`, and usually a key in `SETTING_KEYS` in app.py.
- `scores.py` turns raw feed data into views (which games to show, status text, `is_close`, change wording); `espn.py`/`mlb.py` stream and extract only followed games to save RAM; `teams.py` is the team table behind the followed-team picker (several teams per sport via comma lists `team_<sport>`).
- `board.py` (font, layouts, animations), `critters.py` + `extras_*.py` (idle cameos) draw to the panel; `page.py` is the settings page served from RAM.
- Brightness: `app.brightness_for()` combines display on/off, quiet hours, fixed percent, sunrise/sunset (`sun.py`) or clock hours.

## MicroPython gotchas

- Code runs on the board's MicroPython, with tight RAM: avoid big copies, call `gc.collect()` around network/JSON work, stream parse where possible.
- No extended slicing on tuples/lists (`x[::-1]` crashed the board on game end); use `reversed()`/explicit loops.
- `time.ticks_ms()` wraps: always compare with `time.ticks_diff`.
- `test_app.py` fakes the hardware modules and execs `app.py` without `main()`, so tests pass on CPython even when MicroPython would reject something; keep code simple and test-visible.
- Never commit `secrets.py`, `.ota_key`, or `settings_qr*` (they contain the OTA key; the latter is gitignored).
- Error 110 when a phone opens the settings QR is a network timeout (weak WiFi, cellular on), not a code bug.
